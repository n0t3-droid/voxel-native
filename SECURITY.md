# Security Policy

## Supported versions

Voxel Native has no stable release line yet. Security fixes are evaluated
against the current `master` branch and the exact revision named in a report;
older commits and local builds are not promised security support.

## Reporting a vulnerability privately

Do not publish exploit details, secrets, private paths, save data, or a
proof-of-concept in an issue or pull request.

1. Open the repository's **Security** tab and use **Report a vulnerability**
   when GitHub Private Vulnerability Reporting is available.
2. If that private button is unavailable, open a minimal public issue titled
   `Private security contact requested` with no technical details. A maintainer
   can then arrange a private channel through GitHub.

Include the affected revision, platform, impact, minimal reproduction,
preconditions, and any safe mitigation in the private report. Redact tokens,
personal data, absolute workstation paths, saves, and unrelated logs.

The project is maintained on a best-effort basis and does not promise a response
SLA. Maintainers will validate scope before making a public claim, coordinate
disclosure where practical, and credit reporters who request attribution.
